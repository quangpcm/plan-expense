# Deployment Guide - Vercel

## Mini Expense Sharing Web App

Version: 1.0

Status: Ready to use

---

# 1. Mục tiêu

Hướng dẫn deploy ứng dụng Next.js này lên Vercel, kết nối đúng với Firebase project hiện có (Authentication, Firestore, Storage).

Tài liệu giả định:

- Đã có account Vercel.
- Đã có Firebase project đang chạy (project hiện tại: `plan-expense`).
- Code đã được push lên Git remote (GitHub/GitLab/Bitbucket).

---

# 2. Vì sao deploy được đơn giản

Ứng dụng không có Backend riêng, không dùng Cloud Functions, không có server secret nào.

Toàn bộ config Firebase là biến môi trường dạng `NEXT_PUBLIC_*` - an toàn khi lộ ra client, vì được bảo vệ bằng Firebase Security Rules (`firestore.rules`, `storage.rules`), không phải bằng cách giữ bí mật.

Vercel chỉ cần host phần Next.js. Firestore/Storage/Auth vẫn nằm ở Firebase, không di chuyển.

---

# 3. Biến môi trường cần có

Lấy từ Firebase Console → Project Settings → General → Your apps → SDK config, hoặc copy từ `.env.local` hiện tại:

```text
NEXT_PUBLIC_FIREBASE_API_KEY
NEXT_PUBLIC_FIREBASE_AUTH_DOMAIN
NEXT_PUBLIC_FIREBASE_PROJECT_ID
NEXT_PUBLIC_FIREBASE_STORAGE_BUCKET
NEXT_PUBLIC_FIREBASE_MESSAGING_SENDER_ID
NEXT_PUBLIC_FIREBASE_APP_ID
```

Ghi chú: `.env.example` trong repo hiện đang chứa giá trị thật của project `plan-expense` (không phải placeholder). Không sai về mặt bảo mật (API key Firebase Web không phải secret), nhưng nên cân nhắc đổi lại thành placeholder để `.env.example` đúng vai trò là file mẫu, tránh nhầm lẫn nếu sau này có nhiều Firebase project (dev/staging/production).

# 4. Bước 1 - Import project vào Vercel

Chọn một trong hai cách:

## Cách A - Qua Dashboard (khuyến nghị, có CI/CD tự động theo Git)

1. Vào [vercel.com/new](https://vercel.com/new)
2. Chọn "Import Git Repository", chọn repo `plan-expense`
3. Framework Preset: Vercel tự nhận diện `Next.js`, không cần chỉnh
4. Chưa bấm Deploy ngay - qua mục 5 để set Environment Variables trước

## Cách B - Qua Vercel CLI

```bash
npm install -g vercel
vercel login
vercel link
```

---

# 5. Bước 2 - Cấu hình Build Settings

Vercel tự đọc script từ `package.json`, không cần override:

```text
Build Command: npm run build      # chạy "next build --webpack"
Output Directory: (mặc định, Vercel tự nhận diện .next)
Install Command: npm install
```

Lưu ý: `build` script của project cố định dùng `--webpack` (không dùng Turbopack). Không cần sửa gì trên Vercel, chỉ cần biết để không thấy lạ khi xem log build.

---

# 6. Bước 3 - Khai báo Environment Variables

Trong Vercel: Project → Settings → Environment Variables.

Thêm đủ 6 biến ở mục 3, áp dụng cho cả 3 environment:

```text
Production
Preview
Development
```

Nếu chỉ có một Firebase project duy nhất, dùng chung giá trị cho cả 3. Nếu muốn tách project riêng cho Preview (theo khuyến nghị Development Architecture mục 38 "mỗi environment nên dùng Firebase project riêng nếu có thể"), tạo thêm Firebase project phụ và chỉ set giá trị khác cho Preview.

Sau khi thêm biến môi trường, mới bấm Deploy (Cách A) hoặc chạy:

```bash
vercel --prod
```

(Cách B)

---

# 7. Bước 4 - Thêm domain Vercel vào Firebase Authorized Domains

Bắt buộc, nếu không đăng nhập/đăng ký/quên mật khẩu sẽ lỗi trên domain mới.

1. Vào Firebase Console → Authentication → Settings → Authorized domains
2. Thêm domain Vercel cấp, ví dụ:

```text
plan-expense.vercel.app
```

3. Nếu sau này gắn custom domain, thêm domain đó vào danh sách này luôn.

---

# 8. Bước 5 - Deploy Firestore và Storage Rules (riêng, không qua Vercel)

Vercel không deploy rules. Rules phải deploy qua Firebase CLI, độc lập với deploy code:

```bash
firebase deploy --only firestore:rules,storage:rules
```

Nếu quên bước này, code frontend mới đã lên Vercel nhưng rules cũ (hoặc rules default deny-all) vẫn áp dụng trên Firestore/Storage, dẫn tới lỗi `permission-denied` dù code không có bug.

Nên đưa bước này vào checklist mỗi lần `firestore.rules` hoặc `storage.rules` thay đổi, không chỉ lần deploy đầu tiên.

Khi scope liên quan tới `milestones`, `todos`, `expenses.milestoneId`, hoặc `statistic`, release gate tối thiểu trước deploy nên là:

- `npm run test`
- `npm run test:rules`
- `npm run typecheck`
- chạy manual regression cho chuỗi `milestone -> todo -> expense -> statistic`

---

# 9. Bước 6 - Kiểm tra sau khi deploy

- [ ] Mở domain Vercel, đăng ký tài khoản mới thành công
- [ ] Đăng nhập, đăng xuất hoạt động
- [ ] Tạo Plan mới, owner member được tạo đúng
- [ ] Timeline, Statistic, Members load được dữ liệu realtime
- [ ] Console trình duyệt không có lỗi `permission-denied` hoặc `Firebase configuration is missing`
- [ ] Kiểm tra trên mobile viewport (Chrome DevTools hoặc thiết bị thật)

Nếu thấy lỗi `Firebase configuration is missing`, kiểm tra lại mục 6 (thiếu biến môi trường hoặc chưa redeploy sau khi thêm biến - Vercel không tự áp dụng biến môi trường mới vào deployment đã build sẵn, phải trigger deploy lại).

---

# 10. Custom Domain (tuỳ chọn)

1. Vercel: Project → Settings → Domains → Add domain
2. Cập nhật DNS record theo hướng dẫn Vercel hiển thị (CNAME hoặc A record)
3. Sau khi domain hoạt động, quay lại mục 7 để thêm domain này vào Firebase Authorized Domains

---

# 11. Preview Deployment

Mỗi Pull Request hoặc branch push (khi dùng Cách A) tự có một Preview URL riêng dạng `*.vercel.app`.

Nếu cần test đăng nhập trên Preview, domain Preview đó cũng phải được thêm vào Firebase Authorized Domains. Vì domain Preview thay đổi theo từng deployment, cách thực tế hơn là:

- Thêm domain wildcard dạng `*.vercel.app` nếu Firebase Console hỗ trợ, hoặc
- Chỉ test đăng nhập trên Production/staging cố định, dùng Preview để kiểm tra UI/build không cần đăng nhập thật

---

# 12. Kiểm tra trước khi deploy (khuyến nghị chạy local)

```bash
npm run lint
npm run typecheck
npm run test
```

Ba lệnh này không tự chạy trong quá trình build của Vercel. Nếu muốn Vercel tự chặn deploy khi lint/test fail, cấu hình thêm ở Project → Settings → Git → "Ignored Build Step", hoặc dùng GitHub Actions riêng để chạy check trước khi merge vào nhánh deploy.

---

# 13. Rollback

Vercel giữ lại lịch sử các deployment trước đó.

Nếu bản mới có lỗi: Project → Deployments → chọn bản deployment ổn định trước đó → "Promote to Production".

Không cần revert code hoặc deploy lại từ đầu để rollback.

---

# 14. Tổng kết checklist deploy lần đầu

```text
[ ] Push code lên Git remote
[ ] Import project vào Vercel
[ ] Thêm đủ 6 biến NEXT_PUBLIC_FIREBASE_* cho Production/Preview/Development
[ ] Deploy lần đầu
[ ] Thêm domain Vercel vào Firebase Authorized Domains
[ ] Deploy firestore.rules và storage.rules qua Firebase CLI
[ ] Test đăng ký/đăng nhập/tạo Plan trên domain thật
[ ] (Tuỳ chọn) Gắn custom domain, lặp lại bước Authorized Domains
```
