# Deployment Guide - Vercel

## Mini Expense Sharing Web App

Version: 1.0

Status: Ready to use

---

# 1. Mục tiêu

Hướng dẫn deploy ứng dụng Next.js này lên Vercel, kết nối đúng với Firebase project hiện có (Authentication, Firestore) và Cloudflare R2 (media storage).

Tài liệu giả định:

- Đã có account Vercel.
- Đã có Firebase project đang chạy (project hiện tại: `plan-expense`).
- Đã có (hoặc sẽ tạo) một Cloudflare account với R2 bucket.
- Code đã được push lên Git remote (GitHub/GitLab/Bitbucket).

---

# 2. Kiến trúc deploy

Ứng dụng dùng Firebase (Authentication, Firestore) làm data layer chính, và **có một Route Handler server-side** (`/api/storage/presign`) để ký presigned upload URL cho Cloudflare R2 - đây là phần backend đầu tiên của dự án.

Config Firebase Web (`NEXT_PUBLIC_FIREBASE_*`) vẫn an toàn khi lộ ra client vì được bảo vệ bằng Firebase Security Rules (`firestore.rules`), không phải bằng cách giữ bí mật.

Ngược lại, **R2 access key/secret và Firebase Admin service account key là secret thật sự** - phải là server-only env (không tiền tố `NEXT_PUBLIC_`), chỉ Route Handler đọc được, không bao giờ lộ ra bundle client. Đây là điểm khác biệt quan trọng so với trước khi có R2: dự án không còn "không server secret nào" nữa.

Vercel host cả phần Next.js (bao gồm Route Handler này). Firestore/Auth vẫn nằm ở Firebase; media nằm ở Cloudflare R2 - không cái nào di chuyển qua Vercel.

# 3. Biến môi trường cần có

## 3.1 Public (client-safe)

Lấy từ Firebase Console → Project Settings → General → Your apps → SDK config:

```text
NEXT_PUBLIC_FIREBASE_API_KEY
NEXT_PUBLIC_FIREBASE_AUTH_DOMAIN
NEXT_PUBLIC_FIREBASE_PROJECT_ID
NEXT_PUBLIC_FIREBASE_MESSAGING_SENDER_ID
NEXT_PUBLIC_FIREBASE_APP_ID
```

Cộng thêm domain đọc public của R2 (xem mục 4 để tạo):

```text
NEXT_PUBLIC_R2_PUBLIC_BASE_URL   # vd: https://media.plan-expense.com
```

## 3.2 Server-only (secret thật - không thêm tiền tố NEXT_PUBLIC_)

```text
R2_ACCOUNT_ID
R2_ACCESS_KEY_ID
R2_SECRET_ACCESS_KEY
R2_BUCKET_NAME
FIREBASE_ADMIN_PROJECT_ID
FIREBASE_ADMIN_CLIENT_EMAIL
FIREBASE_ADMIN_PRIVATE_KEY
```

`FIREBASE_ADMIN_PRIVATE_KEY` copy nguyên văn từ file JSON service account (field `private_key`), giữ escaped `\n`. Trên Vercel dán cả chuỗi vào ô value (kể cả `-----BEGIN PRIVATE KEY-----` / `-----END PRIVATE KEY-----`).

Ghi chú: `.env.example` trong repo hiện đang chứa giá trị thật của project `plan-expense` cho nhóm `NEXT_PUBLIC_FIREBASE_*` (không phải placeholder). Không sai về mặt bảo mật (API key Firebase Web không phải secret), nhưng nhóm R2/Firebase Admin trong `.env.example` phải luôn là placeholder - không bao giờ commit giá trị thật của nhóm 3.2.

# 4. Bước 0 - Chuẩn bị Cloudflare R2 + Firebase Admin service account

Chỉ cần làm một lần cho mỗi project/environment.

## 4.1 Tạo R2 bucket

1. Cloudflare Dashboard → R2 → Create bucket, đặt tên (vd: `plan-expense-media`).
2. Bucket để public read (ứng dụng không cần private object nào cho media).

## 4.2 Gắn custom domain cho bucket (bắt buộc cho production)

1. R2 bucket → Settings → Public Access → Connect Domain, trỏ một subdomain (vd: `media.plan-expense.com`) qua Cloudflare.
2. **Không dùng** subdomain mặc định `*.r2.dev` cho production - Cloudflare khuyến cáo không dùng vì có rate limit và không có SLA.
3. Domain này chính là giá trị `NEXT_PUBLIC_R2_PUBLIC_BASE_URL`.

## 4.3 Tạo R2 API Token (access key/secret)

1. Cloudflare Dashboard → R2 → Manage R2 API Tokens → Create API Token.
2. Quyền: Object Read & Write, giới hạn vào đúng bucket vừa tạo.
3. Lưu lại `Access Key ID`, `Secret Access Key`, và `Account ID` (hiển thị ở R2 overview) - map vào `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_ACCOUNT_ID`.

## 4.4 Tạo Firebase Admin service account

1. Firebase Console → Project Settings → Service Accounts → Generate new private key.
2. Tải file JSON, lấy 3 field: `project_id`, `client_email`, `private_key` - map vào `FIREBASE_ADMIN_PROJECT_ID`, `FIREBASE_ADMIN_CLIENT_EMAIL`, `FIREBASE_ADMIN_PRIVATE_KEY`.
3. Không commit file JSON này vào git.

# 5. Bước 1 - Import project vào Vercel

Chọn một trong hai cách:

## Cách A - Qua Dashboard (khuyến nghị, có CI/CD tự động theo Git)

1. Vào [vercel.com/new](https://vercel.com/new)
2. Chọn "Import Git Repository", chọn repo `plan-expense`
3. Framework Preset: Vercel tự nhận diện `Next.js`, không cần chỉnh
4. Chưa bấm Deploy ngay - qua mục 7 để set Environment Variables trước

## Cách B - Qua Vercel CLI

```bash
npm install -g vercel
vercel login
vercel link
```

# 6. Bước 2 - Cấu hình Build Settings

Vercel tự đọc script từ `package.json`, không cần override:

```text
Build Command: npm run build      # chạy "next build --webpack"
Output Directory: (mặc định, Vercel tự nhận diện .next)
Install Command: npm install
```

Lưu ý: `build` script của project cố định dùng `--webpack` (không dùng Turbopack). Không cần sửa gì trên Vercel, chỉ cần biết để không thấy lạ khi xem log build.

Route Handler `/api/storage/presign` khai báo `export const runtime = 'nodejs'` - Vercel tự chạy nó dưới dạng Serverless Function (Node.js), không cần cấu hình thêm.

---

# 7. Bước 3 - Khai báo Environment Variables

Trong Vercel: Project → Settings → Environment Variables.

Thêm đủ các biến ở mục 3.1 và 3.2, áp dụng cho cả 3 environment:

```text
Production
Preview
Development
```

Nếu chỉ có một Firebase project / R2 bucket duy nhất, dùng chung giá trị cho cả 3. Nếu muốn tách project riêng cho Preview (theo khuyến nghị Development Architecture mục 38 "mỗi environment nên dùng Firebase project riêng nếu có thể"), tạo thêm Firebase project và R2 bucket phụ, chỉ set giá trị khác cho Preview.

Sau khi thêm biến môi trường, mới bấm Deploy (Cách A) hoặc chạy:

```bash
vercel --prod
```

(Cách B)

# 8. Bước 4 - Thêm domain Vercel vào Firebase Authorized Domains

Bắt buộc, nếu không đăng nhập/đăng ký/quên mật khẩu sẽ lỗi trên domain mới.

1. Vào Firebase Console → Authentication → Settings → Authorized domains
2. Thêm domain Vercel cấp, ví dụ:

```text
plan-expense.vercel.app
```

3. Nếu sau này gắn custom domain, thêm domain đó vào danh sách này luôn.

# 9. Bước 5 - Deploy Firestore Rules (riêng, không qua Vercel)

Vercel không deploy rules. Rules phải deploy qua Firebase CLI, độc lập với deploy code:

```bash
firebase deploy --only firestore:rules
```

Nếu quên bước này, code frontend mới đã lên Vercel nhưng rules cũ (hoặc rules default deny-all) vẫn áp dụng trên Firestore, dẫn tới lỗi `permission-denied` dù code không có bug.

Nên đưa bước này vào checklist mỗi lần `firestore.rules` thay đổi, không chỉ lần deploy đầu tiên.

Lưu ý: authorization cho media upload/read **không còn nằm trong Firebase Storage Rules** (đã bỏ `storage.rules`) - nó nằm trong code của Route Handler `/api/storage/presign` (`src/app/api/storage/presign/route.ts`). Khi sửa logic quyền upload media, sửa file này và deploy qua Vercel như code bình thường, không cần lệnh `firebase deploy` riêng.

Khi scope liên quan tới `milestones`, `todos`, `expenses.milestoneId`, hoặc `statistic`, release gate tối thiểu trước deploy nên là:

- `npm run test`
- `npm run test:rules`
- `npm run typecheck`
- chạy manual regression cho chuỗi `milestone -> todo -> expense -> statistic`

# 10. Bước 6 - Kiểm tra sau khi deploy

- [ ] Mở domain Vercel, đăng ký tài khoản mới thành công
- [ ] Đăng nhập, đăng xuất hoạt động
- [ ] Tạo Plan mới, owner member được tạo đúng
- [ ] Timeline, Statistic, Members load được dữ liệu realtime
- [ ] Tạo expense có ảnh đính kèm: ảnh PUT thẳng lên R2 thành công, expense detail hiển thị được ảnh qua `NEXT_PUBLIC_R2_PUBLIC_BASE_URL`
- [ ] Thử upload attachment bằng tài khoản role `viewer` - phải bị từ chối với lỗi 403 từ `/api/storage/presign`
- [ ] Console trình duyệt không có lỗi `permission-denied`, `Firebase configuration is missing`, hoặc lỗi từ `/api/storage/presign`
- [ ] Kiểm tra trên mobile viewport (Chrome DevTools hoặc thiết bị thật)

Nếu thấy lỗi `Firebase configuration is missing`, kiểm tra lại mục 7 (thiếu biến môi trường hoặc chưa redeploy sau khi thêm biến - Vercel không tự áp dụng biến môi trường mới vào deployment đã build sẵn, phải trigger deploy lại).

Nếu upload attachment lỗi 500 từ `/api/storage/presign`, kiểm tra lại nhóm biến server-only ở mục 3.2 (R2 credentials hoặc Firebase Admin service account thiếu/sai).

# 11. Custom Domain (tuỳ chọn)

1. Vercel: Project → Settings → Domains → Add domain
2. Cập nhật DNS record theo hướng dẫn Vercel hiển thị (CNAME hoặc A record)
3. Sau khi domain hoạt động, quay lại mục 8 để thêm domain này vào Firebase Authorized Domains

# 12. Preview Deployment

Mỗi Pull Request hoặc branch push (khi dùng Cách A) tự có một Preview URL riêng dạng `*.vercel.app`.

Nếu cần test đăng nhập trên Preview, domain Preview đó cũng phải được thêm vào Firebase Authorized Domains. Vì domain Preview thay đổi theo từng deployment, cách thực tế hơn là:

- Thêm domain wildcard dạng `*.vercel.app` nếu Firebase Console hỗ trợ, hoặc
- Chỉ test đăng nhập trên Production/staging cố định, dùng Preview để kiểm tra UI/build không cần đăng nhập thật

---

# 13. Kiểm tra trước khi deploy (khuyến nghị chạy local)

```bash
npm run lint
npm run typecheck
npm run test
```

Ba lệnh này không tự chạy trong quá trình build của Vercel. Nếu muốn Vercel tự chặn deploy khi lint/test fail, cấu hình thêm ở Project → Settings → Git → "Ignored Build Step", hoặc dùng GitHub Actions riêng để chạy check trước khi merge vào nhánh deploy.

---

# 14. Rollback

Vercel giữ lại lịch sử các deployment trước đó.

Nếu bản mới có lỗi: Project → Deployments → chọn bản deployment ổn định trước đó → "Promote to Production".

Không cần revert code hoặc deploy lại từ đầu để rollback.

Lưu ý: rollback code trên Vercel không rollback logic quyền trong `/api/storage/presign` một cách tách biệt - vì logic đó nằm chung trong code, rollback deployment sẽ tự kéo theo cả route handler.
