# 3. Quyết định kỹ thuật đã chốt

## 3.1 Milestone compatibility anchor

V1.1 chưa refactor bỏ `milestone` khỏi Finance persistence.

Rule:

- nếu plan bật `planning` module, milestone hoạt động bình thường
- nếu plan không bật `planning` nhưng `finance` vẫn cần milestone reference, app tự tạo đúng 1 hidden milestone
- hidden milestone có `isSystemHidden: boolean`

## 3.2 Hidden milestone lifecycle

- tạo lúc create plan
- mỗi plan không có `planning` chỉ có đúng 1 hidden milestone
- không edit
- không delete
- không reorder
- không hiển thị lên planning UI
- không hiển thị trong selector của user
- expense/income form auto-fill ngầm

## 3.3 Transitional architecture của Finance

Trong V1.1:

- Finance độc lập ở UX/navigation/composition
- Finance chưa độc lập hoàn toàn ở persistence
- `milestoneId` vẫn là compatibility anchor cho schema/service/statistic/aggregate/rules/tests

## 3.4 Phase đầu của Module Registry

Module Registry V1.1 chỉ cần quản lý:

- navigation
- overview widgets
- capability map
- route ownership / collection ownership metadata

Chưa cần generic hóa toàn bộ domain service ngay ở phase đầu.

# 4. Hiện trạng codebase

## 4.1 Điểm đã sẵn sàng

- `Plan` đã có `planType`
- category preset đã map theo `planType`
- milestone template đã map theo `planType`
- dữ liệu đang xoay quanh `/plans/{planId}/...`
- `wedding-guest` đã là extension module tương đối tách biệt

## 4.2 Điểm đang coupling

### Plan detail

`src/app/(authenticated)/plans/[planId]/page.tsx`

Hiện đang:

- hard-code tabs
- import trực tiếp nhiều module
- special-case `wedding`
- chưa render theo `PlanTypeConfig + ModuleRegistry`

### Permission

`src/modules/member/services/permission.service.ts`

Hiện đang:

- trả về boolean cố định như `canManageWeddingGuest`
- chưa đi theo capability/module map

### Finance

`src/modules/expense/services/expense.service.ts`

`src/modules/income/services/income.service.ts`

Hiện đang:

- yêu cầu milestone
- assume user sẽ chọn milestone từ UI
- chưa có khái niệm hidden system milestone

### Plan create/delete

`src/modules/plan/repositories/firestore-plan.repository.ts`

Hiện đang:

- tạo milestone template theo `planType`
- chưa có `PlanTypeConfig`
- chưa có hidden milestone flow
- delete plan vẫn hard-code subcollection names

# 9. Phase 2 - Hidden Milestone Compatibility Layer

## 9.1 Mục tiêu

Giữ nguyên compatibility của Finance hiện tại nhưng hỗ trợ plan không có planning UI.

## 9.2 Output chính

- milestone có `isSystemHidden`
- create plan flow tạo hidden milestone khi cần
- expense/income auto-resolve hidden milestone
- planning UI không lộ hidden milestone

## 9.3 Task Breakdown

### Data model

Update milestone schema/document:

- thêm `isSystemHidden: boolean`

Update DMS và repository mapping tương ứng.

### Plan create flow

`src/modules/plan/repositories/firestore-plan.repository.ts`

Refactor `createPlanGraph()`:

- không chỉ dựa vào `planType` cũ
- resolve module config trước
- nếu `planning` enabled:
  - tạo milestone templates bình thường
- nếu `planning` disabled và `finance` enabled:
  - tạo đúng 1 hidden milestone

### Runtime resolver

Tạo helper:

- `resolveDefaultMilestoneForPlan(planId, milestones, config)`

Rule:

- nếu planning enabled thì dùng flow hiện tại
- nếu planning disabled thì resolve hidden milestone

### Expense / Income service

`src/modules/expense/services/expense.service.ts`

`src/modules/income/services/income.service.ts`

Refactor:

- cho phép UI không truyền milestone selector khi planning disabled
- service tự gán hidden milestone
- vẫn giữ `milestoneId` bắt buộc ở persistence layer

### UI filtering

Filter hidden milestone khỏi:

- milestone list
- milestone search
- milestone selector
- planning statistic UI

Không filter hidden milestone khỏi:

- internal aggregation
- finance totals cấp plan

## 9.4 File/Area dự kiến bị ảnh hưởng

- `src/modules/milestone/types/milestone.ts`
- `src/modules/milestone/repositories/firestore-milestone.repository.ts`
- `src/modules/plan/repositories/firestore-plan.repository.ts`
- `src/modules/expense/services/expense.service.ts`
- `src/modules/income/services/income.service.ts`
- `src/modules/expense/components/expense-form.tsx`
- `src/modules/income/components/income-form.tsx`
- `src/modules/statistic/services/statistic.service.ts`

## 9.5 Checklist Pass

- debt/general style plan có thể chạy finance mà không lộ planning UI
- wedding/travel vẫn hoạt động như cũ
- statistic tổng không sai
- hidden milestone không hiện lên UI

# 12. Phase 5 - PlanDetail Navigation and Tab Composition

## 12.1 Mục tiêu

Tách `PlanDetail` khỏi hard-coded tab list và plan-type checks.

## 12.2 Output chính

- tab/navigation sinh từ config
- module screen map
- `PlanDetail` generic hơn

## 12.3 Task Breakdown

### Navigation model

Refactor:

`src/app/(authenticated)/plans/[planId]/page.tsx`

Hiện trạng:

- hard-coded `tabs`
- `TAB_BY_QUERY_PARAM`
- special-case `plan.planType === 'wedding'`

Mục tiêu:

- derive visible modules từ `PlanTypeConfig`
- map module sang tab item
- map query param sang module/tab

### Screen composition

Tách render block theo module:

- overview section
- planning section
- finance section
- members section
- wedding guest section

Giai đoạn đầu chưa cần chia nhỏ toàn bộ page thành nhiều route con.

Có thể dùng pattern:

- `moduleRenderers`
- `tabDefinitions`
- `moduleScreenMap`

### Backward-safe strategy

Không rewrite toàn file `PlanDetail` một lần.

Nên làm theo bước:

1. tạo derived navigation model
2. thay phần tab header bằng model mới
3. thay từng block render theo module id
4. giữ logic business cũ đến khi flow pass

## 12.4 Checklist Pass

- wedding không cần special-case tab
- travel có thể hiện `planning + itinerary + finance + members`
