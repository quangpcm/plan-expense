# 1. Implementation Specification Purpose

Implementation Specification là bridge cuối cùng giữa:

```text
DESIGN SYSTEM SPECIFICATION
        ↓
AUDIT
        ↓
AUDIT DECISIONS
        ↓
IMPLEMENTATION SPECIFICATION  ← chúng ta đang ở đây
        ↓
CODE
        ↓
PILOTS
        ↓
REGRESSION
        ↓
BROAD MIGRATION
```

Nó **không thiết kế lại Design System**.

Những quyết định đã freeze trong Design System V2 và Audit Decision Record không được mở lại chỉ vì implementation khó.

Implementation Specification chịu trách nhiệm định nghĩa:

- file/folder architecture;
- token architecture;
- CSS/Tailwind mapping;
- component contracts;
- component ownership;
- migration boundaries;
- dependency order;
- implementation waves;
- acceptance criteria;
- regression contracts;
- rollout strategy.

# 3. Implementation Non-Goals

V2 migration **không phải**:

```text
architecture rewrite
business rewrite
data model cleanup
permission redesign
Firestore cleanup
repository refactor
feature redesign
copywriting redesign
routing redesign
```

Không được dùng Design System migration như lý do để sửa technical debt ngoài scope.

Ví dụ coding agent thấy:

```ts
canEditAllExpenses;
```

nhưng Income không có equivalent.

Không được:

> "Tiện thể normalize permission."

Đây là Product/Permission Debt, không phải DS migration.

# 7. Token Implementation Strategy

Đây là **Wave đầu tiên thực sự được phép sửa code**.

Nhưng không migrate consumer ngay lập tức.

Target:

```text
Raw palette
        ↓
Semantic tokens
        ↓
Component tokens/usage
```

Ví dụ conceptual:

```text
raw.indigo.500
raw.blue.500
raw.red.500

        ↓

brand.primary
text.primary
text.secondary
surface.default
surface.subtle
border.default
status.danger
status.success
```

Consumer không nên dùng raw palette khi semantic token tồn tại.

---

# 8. Color Token Categories

Minimum semantic categories:

```text
brand.*

surface.*

text.*

border.*

interactive.*

status.*

focus.*

overlay.*
```

Plan-Type Expression có thể có:

```text
plan.travel.*
plan.wedding.*
plan.debt.*
...
```

nhưng các token này chỉ expression.

Không chứa business meaning.

Ví dụ hợp lệ:

```text
plan.wedding.accent
```

Không hợp lệ:

```text
plan.wedding.guestConfirmed
```

Guest confirmed là product semantic.

# 9. Finance Color Contract

Đây là implementation invariant từ Audit Decision Record:

```text
money.amount.default
→ neutral
```

Không:

```text
expense → red
income → green
```

mặc định.

Semantic status mới dùng:

```text
status.success
status.warning
status.danger
```

Coding agent không được mass replace:

```text
text-green-* → status.success
text-red-*   → status.danger
```

Phải inspect semantic context.

# 10. Typography Implementation

Không dùng typography bằng arbitrary combination ở consumer:

```text
text-sm font-medium leading-5
```

lặp lại khắp nơi nếu nó đại diện cùng semantic role.

V2 cần semantic roles như:

```text
page-title
section-title
component-title

body
body-strong

metadata
caption

metric-lg
metric-md
metric-sm
```

Implementation có thể dùng utility composition hoặc component-level recipe tùy stack hiện tại.

**Không tạo React component cho mọi typography role.**

Ví dụ không cần:

```tsx
<PageTitle />
<SectionTitle />
<Metadata />
```

nếu CSS/token class đã giải quyết tốt.

---

# 11. Spacing Implementation

Spacing tiếp tục theo V2 scale.

Không cần xóa mọi arbitrary spacing ngay lập tức.

Migration classification:

```text
semantic repeated spacing
→ TOKENIZE

true one-off layout adjustment
→ KEEP LOCAL

legacy arbitrary spacing
→ migrate when consumer touched
```

Không chạy codemod thay tất cả.

---

# 13. Elevation Implementation

Elevation phải trở thành **semantic hierarchy**, không phải decoration.

Ví dụ:

```text
elevation.none

```

Không nên tạo:

```text

shadow-md
shadow-lg
shadow-xl
```

rồi consumer tự chọn theo cảm tính nếu Design System không cần nhiều level như vậy.

Default Card:

```text
shadow = none
```

trừ khi role yêu cầu surface separation.

---

# 14. Focus Implementation

Focus là P1.

Tất cả interactive primitives phải có canonical:

```text
focus-visible
```

Không được:

```css
outline: none;
```

mà không có replacement.

Focus token nên bao gồm:

```text
focus.ring
focus.offset
focus.color
```

và được primitive sở hữu.

Product component không tự thiết kế focus riêng.

---

# 15. Motion Implementation

Motion dùng cho:

```text
state transition
overlay
collapse
feedback
```

không dùng chỉ để "app trông premium hơn".

V2 phải support:

```text
prefers-reduced-motion
```

Animation decorative có thể disable.

State transition cần giữ usability.

# 16. Primitive Migration Rule

Primitive migration phải giữ public behavior càng nhiều càng tốt.

Ví dụ:

```text
Button V1
↓
Button V2
```

ưu tiên giữ:

```text
onClick
disabled
type
ref
aria-*
```

Nếu variant API cần đổi:

```text
old API
↓ compatibility
new API
↓ migrate consumers
↓ remove compatibility
```

Không đổi 40 consumers cùng lúc nếu adapter giải quyết an toàn hơn.
