## 7. Targeted P0/P1 verification

`AttachmentPicker` is always rendered inside a form that is itself inside a `ResponsiveModal`
(`ExpenseForm`, `DebtTransactionForm`, `TravelActivityForm`, `TodoVendorForm`, `TodoForm`), so this
migration is the first case of a `ResponsiveModal` **nested inside another `ResponsiveModal`** with
live form content on both layers — a materially different composition from the previously-proven
"detail view + `ConfirmDialog` on top" stacking (e.g. `TodoDetailView` + delete confirm in Plan
Detail Shell). That is a new-behavioral-risk trigger under this wave's process, so a small isolated
browser check was run rather than skipped outright — proportional to the risk, not an exhaustive
matrix.

Method: temp route `src/app/wave1-verify-temp/page.tsx` (outside any route group, mock state only,
no Firestore) rendering an outer `ResponsiveModal` with `AttachmentPicker` inside, driven by
Playwright (`playwright-core@1.62.1`, cached Chromium binary, same harness convention as prior
waves), at both desktop (1280×900, Dialog-in-Dialog) and mobile (390×844, Drawer-in-Drawer)
viewports. Route + `.next` cache deleted after; final diff contains only the one product file.

Checked and confirmed on both viewports:
- Outer modal opens; triggering the picker opens the inner modal on top (both mounted
  simultaneously — not a replace).
- URL-entry step: invalid URL still shows `"Đường dẫn không hợp lệ."`; valid URL still calls
  `onChange` with the new draft and closes the inner modal (`drafts count: 1` observed).
- Escape closes only the topmost (inner) overlay; the outer modal stays open and its trigger is
  fully interactive afterward, correctly reopening the inner modal a second time.

One false-alarm dead end worth recording for future waves, not a defect: right after opening the
inner modal, Playwright's `locator.isVisible()` reported the outer heading as **not** visible on
both viewports. Direct DOM inspection showed the outer content was still `display:block`,
`visibility:visible`, fully in the DOM — it had `aria-hidden="true"` set on an ancestor, which is
Radix's standard "hide background content from assistive tech while a nested dialog/drawer is
active" behavior (the same mechanism already exercised by `TodoDetailView` + delete-confirm
stacking), and which Playwright's `isVisible()` treats as not-visible even though the DOM/CSS state
is untouched. A second false alarm on mobile only ("outer still open" read `false` right after
Escape) was traced to the same cause plus vaul's close-transition duration exceeding the test's
wait window — waiting the transition out and re-querying confirmed the outer drawer was open,
mounted, and interactive the entire time. No code change was needed for either; both were test-harness
timing, not product behavior.
