## 6. Calculation / business / data changes: **NO**

- No file in `statistic.service.ts`, `utils/fund-balance.ts`, or any type/schema was touched.
- Every migrated component still receives and displays the exact same `StatisticResult` fields it
  did before — `overview.totalExpense`, `overview.settledAmount`, `overview.pendingSettlementAmount`,
  `fund.unallocatedBalance`, `fund.allocatedIncome`, `fund.totalIncome`, `overview.totalIncome`,
  `overview.memberCount`, `overview.expenseCount`, `categoryBreakdown[].totalAmount` — verified
  field-by-field against the diff (no field substitution, no reordering that could transpose a
  label onto the wrong value).
- **Color-fidelity discipline applied per value, not assumed**: before using `Metric`'s `tone`
  system anywhere, I checked whether the token it resolves to is byte-identical to what the
  original literal color was:
  - `FinanceSummaryHero`'s `--color-success`/`--color-warning` usage → **exact match** to
    `Metric`'s `tone="success"`/`"warning"` (`--color-status-success: var(--color-success)`,
    `--color-status-warning: var(--color-warning)` — confirmed in `globals.css`). Migrated directly.
  - `StatisticOverview`'s "Tổng thu" `text-emerald-700` → **not** an exact match to `tone="success"`
    (`--color-status-success` resolves to `#059669` = Tailwind `emerald-600`, not `emerald-700`
    = `#047857` — different shades). Rather than silently shift the shade or strip the color
    (either of which is a real, if subtle, unrequested design decision), the exact literal class
    was preserved by wrapping just the value in `<span className="text-emerald-700">` inside
    `Metric`'s `value` slot — confirmed in rendered HTML and via a targeted computed-style check
    that this span (not `Metric`'s own wrapper) carries the color, so the rendered pixel color is
    byte-identical to before.
  - `Metric`'s "plain neutral" default tone (`--color-text-primary` = `#172033`) is **not**
    byte-identical to the literal `text-slate-950` (`#020617`) it replaces in several cells. This
    was **not** treated as a preservation violation — it's the Design System's own defined neutral,
    the same one every prior Pilot/Wave's `Metric` adoption already accepts app-wide; re-litigating
    it per-consumer would contradict the already-approved component's own contract.
- **Financial color semantics were not changed, and one pre-existing inconsistency was found but
  deliberately not touched**: `StatisticOverview`'s green "Tổng thu" colors a plan-wide aggregate
  (not a member's own balance), which is a pre-existing exception to the established "red/green =
  member balance only" principle. This predates this wave and isn't something a presentation-only
  migration should silently "fix" (that would be a financial-color-meaning judgment call, not a
  structural migration) — preserved exactly as-is and flagged in §10.

## 8. Targeted P1 verification

- Overlays: none migrated this wave (module had none).
- Structural layout: `MetricGroup`'s fixed column-breakpoint presets (`columns={3}` =
  `grid-cols-2 sm:grid-cols-3`; `columns={4}` = `grid-cols-2 sm:grid-cols-4`) don't exactly match
  the originals' custom breakpoints (`FinanceSummaryHero`/`FundBalanceCard` were
  `grid-cols-1 sm:grid-cols-3`; `StatisticOverview` was `grid-cols-2 xl:grid-cols-4`) — `MetricGroup`
  offers only 3 fixed presets, no custom-breakpoint escape hatch. Accepted as a minor P2 responsive
  delta (not "clearly unusable" at any width — worst case is 2-of-3 or 2-of-4 cells per row on
  narrow/tablet viewports instead of a different split), consistent with this wave's own stated P2
  threshold. Not screenshot-matrix-verified across breakpoints, per the "no exhaustive matrices"
  instruction.
- Typography: `Metric`'s 3 fixed sizes (`sm`=18px, `md`=22px, `lg`=28px, all `font-bold`) don't
  exactly match the originals' arbitrary sizes/weights (e.g. `text-2xl font-semibold` = 24px/600,
  `text-lg font-medium` = 18px/500 for `FundBalanceCard`'s two supporting cells). Picked the closest
  size per cell; the weight/color convergence to bold means `FundBalanceCard`'s two "supporting"
  cells (`Đã phân bổ`, `Tổng đã nạp quỹ`) lose their original de-emphasis relative to the headline
  cell (`Quỹ chưa phân bổ`) on the weight/color axis, though the still-large size gap (28px vs 18px)
  preserves the same relative-importance signal. Flagged as an accepted P2 delta, not a blocker.
