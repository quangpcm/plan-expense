# 1. Audit Purpose

Mục tiêu của Audit không phải:

> tìm tất cả UI xấu để sửa.

Mục tiêu là xác định:

> **Hiện tại Go Plan đang có những foundation/component/pattern nào, cái nào phù hợp V2, cái nào cần thay đổi, và migration dependency thực tế ra sao.**

Audit phải tạo được 5 output:

```text
1. Current UI inventory
2. Inconsistency registry
3. Component disposition
4. Migration dependency map
5. Pilot readiness assessment
```

Audit không được thay đổi business.

Architecture hiện tại đã tách UI → Hook → Service → Repository → Firebase và yêu cầu business logic chỉ nằm ở Service; đây là boundary bắt buộc khi phân loại UI/component. 

---

# 2. Audit Scope

Audit gồm 8 lớp:

```text
Foundation
Components
Patterns
Screens
Responsive
Accessibility
Domain leakage
Migration dependencies
```

Không audit sâu:

* business algorithm correctness;
* Firestore schema correctness;
* security redesign;

trừ khi UI hiện tại đang leak/chạm sai boundary.

---

# 3. Audit Evidence Levels

Mỗi finding phải gắn evidence:

### `CONFIRMED`

Được source/code xác nhận rõ.

### `OBSERVED`

Được screenshot/UI hiện tại thể hiện rõ.

### `NEEDS CODE AUDIT`

Tài liệu cho biết concept tồn tại nhưng chưa đủ để kết luận implementation cụ thể.

### `OUT OF DS SCOPE`

Finding thuộc business/product architecture, không phải Design System.

Điều này giúp tránh việc specification biến thành assumption.

---

# 4. Component Disposition Vocabulary

Mỗi item được phân loại:

| Status               | Meaning                                          |
| -------------------- | ------------------------------------------------ |
| **KEEP**             | Architecture/API đã phù hợp, chỉ cần token/style |
| **ADAPT**            | Concept đúng, cần chỉnh anatomy/API/style        |
| **REPLACE**          | Pattern hiện tại không còn phù hợp V2            |
| **MERGE**            | Nhiều component giải cùng một problem            |
| **PRODUCT-SPECIFIC** | Giữ trong domain, không đưa vào core DS          |
| **DEPRECATE**        | Cho V1 dùng tạm, không mở rộng                   |
| **REMOVE**           | Không còn consumer sau migration                 |
| **REVIEW**           | Chưa đủ evidence                                 |

# 37. Audit Gate

Audit chỉ hoàn thành khi có:

```text
[ ] Foundation inventory
[ ] Actual component inventory from repo
[ ] Pattern inventory
[ ] Hard-coded style inventory
[ ] Domain leakage findings
[ ] Permission leakage findings
[ ] Accessibility findings
[ ] Responsive findings
[ ] KEEP/ADAPT/REPLACE/... classification
[ ] Migration dependency map
[ ] Design Debt Registry
[ ] Pilot blockers
```

Hiện tại từ documents chúng ta đã có:

```text
Foundation direction          ✓
Architecture boundaries       ✓
Known component vocabulary    ✓
Known product components      partial
Known patterns                partial
Business constraints          ✓
```

Nhưng chưa có:

```text
Actual complete component list
Actual class/token usage
Duplicate components
Exact file dependency graph
Accessibility implementation state
Responsive implementation state
```

Các phần này **bắt buộc phải audit codebase thực tế**, không thể suy ra an toàn từ specification.
