# 2. Quy tắc sử dụng Implementation Plan

## 2.1 Thứ tự ưu tiên tài liệu

Khi có mâu thuẫn giữa các tài liệu, ưu tiên theo thứ tự:

1. `DMS` cho data model, collection, field, rule dữ liệu
2. `SDD` và `Development Architecture` cho kiến trúc code, layer, service flow
3. `UI/UX` cho flow màn hình và hành vi tương tác
4. `PRD` cho scope sản phẩm và mức ưu tiên MVP
5. `Implementation Plan` cho thứ tự triển khai và task execution

## 2.2 Quy tắc cập nhật khi scope thay đổi

Khi có update mới từ Product hoặc User khác với spec hiện tại:

1. Xác định tài liệu nào bị ảnh hưởng.
2. Update tài liệu spec gốc trước.
3. Update `Implementation Plan` nếu thứ tự hoặc task triển khai bị thay đổi.
4. Chỉ bắt đầu code sau khi tài liệu đã đồng nhất.

Ví dụ:

- thay đổi field hoặc collection: update `DMS`
- thay đổi flow màn hình: update `UI/UX`
- thay đổi architecture hoặc layer: update `SDD` hoặc `Development Architecture`
- thay đổi scope MVP: update `PRD`
- thay đổi thứ tự làm hoặc checklist pass: update `Implementation Plan`

## 2.3 Definition of Pass

Một phase được coi là `Pass` khi:

- task bắt buộc của phase đã hoàn thành
- checklist pass của phase đã đạt
- không còn blocker kỹ thuật trong phạm vi phase đó
- code của phase không phá vỡ flow đã hoàn thành ở phase trước

# 3. Nguyên tắc triển khai

- Bám chặt flow MVP: `Create Plan -> Add Member -> Create Expense -> Timeline -> Statistic -> Settlement`
- Ưu tiên mobile-first ngay từ đầu
- Business logic chỉ nằm ở `Service`
- Realtime state đi qua `Repository.watch()` và `Service`
- Chỉ implement những gì MVP yêu cầu
- `SplitService` MVP chỉ implement `equal()`
- `Statistic` luôn tính runtime, không lưu aggregate statistic riêng
- Chỉ dùng `memberId` trong phạm vi plan cho expense, income, settlement
- Mọi update nhiều document phải đi qua `transaction` hoặc `batched write` khi cần nhất quán
- Không code UI vượt trước domain model và service contract

- Nếu có update mới từ User khác với spec, phải cập nhật tài liệu liên quan để đồng nhất rồi mới code tiếp.
- `Implementation Plan` là tài liệu execution, không thay thế `DMS`, `SDD`, `UI/UX` hay `PRD`.
